# Getting Started with ROS2 (Linux/WSL)

Our target platforms for these guides are:

* [Bitcraze CrazyFlie 2.1+](https://www.bitcraze.io/products/crazyflie-2-1-plus/)
* [iRobot Create 3](https://iroboteducation.github.io/create3_docs/)

We need to pick a ROS release that works for each of those.  We'll aim for [Jazzy Jalisco](https://docs.ros.org/en/jazzy/index.html) for the Create and Humble for the Crazyflie, however that may change.

I will be testing this out on EndeavorOS (Arch-based), Linux Mint (Debian-based), and WSL2 on Windows.  If you use a different distribution then you'll need to follow a [ROS installation guide for your platform](https://docs.ros.org/en/jazzy/Installation.html).

## Environment

You need a terminal environment that has the ability to (1) use Docker and (2) install [distrobox](https://github.com/89luca89/distrobox).  While you will always end up with better performance natively installing ROS, distrobox/Docker will give flexibility for installing the different versions of ROS we'll need for each platform.  

distrobox is a nice tool for managing local operating system installs within your terminal without the need for virtual machines.  If you want to skip this aspect and are interested in simply using Docker then here is the [ROS guide](https://docs.ros.org/en/kilted/How-To-Guides/Run-2-nodes-in-single-or-separate-docker-containers.html). 

*Note: all guides will assume you're using distrobox from here on out*

> You could also consider using a virtual machine, though in my experience that leads to slower simulations.  However, you get a 'bare metal' installation that way and have full control over the operating system, so that's nice.

## Docker setup

You have your choice of Docker, podman, or lillipod for container management.  I personally went with Docker just due to familiarity, but it comes down to personal preference.  

Follow the instructions on the [Docker website](https://www.docker.com/) to setup the tool.

> Note that you may need to enable hardware-assisted virtualization in your system BIOS if the installation fails!  Check the logs for what the problem is if necessary.  Here is a Github Gist that outlines the steps for updating BIOS: [https://gist.github.com/bonartm/2b754a61218daa9da64e94da620d8f18](https://gist.github.com/bonartm/2b754a61218daa9da64e94da620d8f18)
{: .prompt-tip }

### Docker service

You also need to make sure the Docker service is running as well, otherwise distrobox will have problems functioning.  If you are on Windows then this *should* be automatically setup as part of the installation.

If you are on Mac then unfortunately you'll need to check on your own - I don't have a Mac I can test with.  In theory it should also autostart.

For Linux, assuming you're on `systemd`, just run the following (note - this holds for WSL as well).  These commands ensure that Docker runs on reboot and starts:

```bash
$ sudo systemctl enable docker.service
$ sudo systemctl start docker.service
```

The post-installation instructions may be helpful as well: [Linux post-installation steps for Docker Engine](https://docs.docker.com/engine/install/linux-postinstall/)

## Setup ROS 2 Jazzy

First, we're going to tweak the `.bashrc` file.  At the end add this (you can do this on your host system or within the container - it's the same file):

```bash
# distrobox only
if [ -e /run/.containerenv ] || [ -e /.dockerenv ]; then
  # distrobox-only settings go here
  alias update='sudo apt update && sudo apt upgrade -y'
  export PS1="\[\e[32m\]distrobox> \[\e[m\]\w\$ "
  export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
fi
```

This will set ROS to tweak the RMW_IMPLEMENTATION flag that will be useful later on.  If you have any other distrobox specific settings (that you don't want polluting your main terminal environment put them within the `if` block as well).

> The `PS1` command tweaks the name of the environment in the terminal so you see `distrobox>` for entering commands.  The `update` command is a helper alias for running `sudo apt update && sudo apt upgrade`` in one quick command -- try it out!
{: .prompt-tip }

Before we get started, try out the `update` command.  First you need to re-source your `.bashrc` file (or simply exit and reenter jazzy).

```bash
source ~/.bashrc
update
```

Ok, time to install ROS now!  This is known as **the difficult part**.

> We're going to follow the [Jazzy installation guide](https://docs.ros.org/en/jazzy/Installation.html).

Since we're in Ubuntu we can use the `deb` based approach.  If you picked a different OS then follow that guide -- we'll assume Ubuntu.  Follow this guide to the letter, including the **Try some examples** section to make sure it works: [https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html)

> **WARNING - SKIP THE FULL UPGRADE!  WE NEED TO STAY ON UBUNTU 24 OTHERWISE JAZZY DOESN'T WORK**

## Generic setup guide

The Create 3 setup held your hand a bit (though it probably doesn't feel like it).  Other ROS setups will not.  Here is your general process when building from source:

1. Create a workspace folder (we called ours `create3_ws`) and then a source folder inside there (`create3_ws/src`)

2. Clone your robot's project repository into that `src` and follow any/all dependency installation or build instructions.

* The following is what we 'assume' we'll have to do.  Sometimes it is part of Step 2 and sometimes it isn't.  For example, the Crazyflie documentation doesn't mention it, but the Create 3 documentation does.

3. In the main workspace folder, install dependencies with `rosdep`: `rosdep install --from-path src -yi`

4. Build the workspace: `colcon build --symlink-install`

5. Source the install script (and potentially add to your `~/.bashrc` file using a direct path): `source install/local_setup.bash`

6. Run with an appropriate `ros2 run` command (this will vary per project)

> If you ever get into a place where your environment is broken or has things that are wonky and you want to do a `clean`, you can recursively delete the `build` and `install` (and potentially `log`) directories.

## Setup Crazyflie

Now this is fun.  There are a handful of guides for setting up a simulation for the Crazyflie.  HOWEVER, they all differ.  If you follow the [Crazyflie’s Adventures with ROS 2 and Gazebo](https://www.bitcraze.io/2024/09/crazyflies-adventures-with-ros-2-and-gazebo/) guide then you'll end up with a mapper that has no physics collisions.  Useful, but not helpful for our particular circumstances.

We'll use [CrazySim](https://github.com/gtfactslab/CrazySim) as our simulation environment.  The fun part is that it requires Ubuntu 22 and ROS2 Humble.  So go through the same setup steps, but now for a different environment.  

First, make sure you're not in a distrobox environment and then run each of these in order:

```bash
cd ~/distrobox
mkdir humble
cd humble
```

You should now have two folders: `~/distrobox/jazzy` and `~/distrobox/humble`.  Ideally this will keep things separated.

> Again, feel free to use your own folder setup.  This is what makes sense to me.

Back to the steps:

> Don't forget to add `--nvidia` if you have an nvidia GPU!

```bash
distrobox create --image ubuntu:22.04 --name humble
distrobox enter humble
```

Interestingly, you'll see this error (or similar, depending on your setup):

```bash
bash: /opt/ros/jazzy/setup.bash: No such file or directory
not found: "/opt/ros/jazzy/local_setup.bash"
```

This is fine.  Remember the files in your home directory are shared, and your `.bashrc` is trying to source your Jazzy files.  You can either ignore it or fix it up with some bash trickery.  I'm going to ignore it since it isn't a problem.

Next, setup [ROS2 Humble following the guide](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html). Don't forget to update your `.bashrc` file with the appropriate `source` command.  Also, remember you need to do it all again since this is technically a new operating system!

Then, setup [Gazebo Garden](https://gazebosim.org/docs/garden/install_ubuntu/).  Unlike before, here we want everything to be in `humble` -- no jazzy!  Don't forget to install the `ros-dev-tools` as well.

Now setup [CrazySim](https://github.com/gtfactslab/CrazySim).  Note that this isn't controlled by `colcon` so we aren't going to setup the typical `ros2_ws/src` - it'll be its own happy little folder.


```bash
$ cd ~/distrobox/humble
$ git clone https://github.com/gtfactslab/CrazySim.git --recursive
```

You're going to need `git-lfs` here as well, though the instructions don't make that clear and the firmware will silently fail to pull:

```bash
$ sudo apt install git-lfs
$ git lfs install
```

Then, [install cflib](https://github.com/bitcraze/crazyflie-lib-python/blob/master/docs/installation/install.md) - note we'll need to setup another virtual environment:

```bash
$ sudo apt install python3-venv
$ python3 -m venv ~/distrobox/humble/venv
$ source ~/distrobox/humble/venv/bin/activate
$ pip install cflib
```

Now, continue to follow the instructions verbatim inside the CrazySim guide.  The `crazyflie_firmware` folder reference is within the `CrazySim` folder.

> If you receive errors when you launch the simulation, e.g.:

> `MESA: warning: Driver does not support the 0x7d67 PCI ID.`
> `libGL error: glx: failed to create dri3 screen`
> `libGL error: failed to load driver: iris`
> `MESA: warning: Driver does not support the 0x7d67 PCI ID.`
> `libGL error: glx: failed to create dri2 screen`
> `libGL error: failed to load driver: iris`

`export LIBGL_ALWAYS_SOFTWARE=1`

If that works, include it in your `.bashrc` file with the other commands.

## Setup VSCode with distrobox

I'm going to go out on a limb and assume that not everybody prefers to use `vim` in the terminal like I do for editing files.  Since distrobox uses your home directory, all you need to do is point VSCode (or your favorite editor) at the `~/distrobox` directory.

> If you don't have VSCode you can install it [here](https://code.visualstudio.com/).  VSCodium should be fine as well if you prefer a more [open editor](https://vscodium.com/).
